# Первая рабочая версия: Telegram ↔ веб-чат, зеркалирование, несколько ботов

**Закрыто 2026-09-03.** Группа шагов 97–105 (плюс 98, шедший параллельно) — первая версия
интеграции чата (`fractera-chatbot-starter`, движок Vercel AI Chatbot) с Telegram через платформенную
службу каналов (`ai-workspace`, `:3500`).

## Что умеет система сегодня, и чем это доказано

**Полный круг, обе стороны, без ручного вмешательства.** Человек пишет боту в Telegram — сообщение
доезжает до чата, ложится в СВОЙ разговор (свой на пару «бот × собеседник»), модель формирует ответ,
ответ уходит назад тем же ботом. Человек пишет в веб-чате — то же самое в обратную сторону: и его
вопрос, и ответ модели зеркалятся в связанный Telegram, если разговор к нему привязан.
Доказано: живой обмен на реальных ботах `@roma_armstrong`, `@Rada_tnf`, сверка по журналу службы
`:3500` (`inbox.jsonl`) на каждом шаге, негативный контроль на несвязанных разговорах.

**Несколько ботов, у каждого своя история.** Один владелец может привязать более одного бота;
каждый бот ведёт отдельный разговор, сообщения одного никогда не смешиваются с другим. Проверено
полным циклом добавления/удаления бота.

**Область размышления — каркас, не имитация.** Ответу предшествует раскрывающийся блок
«Ход ответа» (`ChainOfThought`, не `reasoning` — см. решения владельца ниже), персистентно хранимый
в той же строке сообщения (`Message_v2.parts`, Data Parts AI SDK), без второй таблицы. Сегодня несёт
один правдивый шаг-заглушку «модель формирует ответ» на обоих путях генерации (браузер и Telegram).

**Лента обновляется без перезагрузки.** `NOTIFY` Postgres → SSE → дорисовка строки; сообщение,
пришедшее в открытую вкладку с любой стороны (Telegram или другая вкладка), появляется само.

**Зеркалирование — обе стороны, включая вложения.** Вопрос человека из веб-чата уходит в Telegram
с пометкой `<b>Web Chat Input Message:</b>` (`parse_mode: HTML`, текст экранирован); ответ модели —
без пометки. Изображение/аудио/документ, приложенные в веб-чате, доезжают до Telegram как отдельное
сообщение через уже существовавшую дверь `/telegram/sendFile` — только для СВЯЗАННЫХ разговоров,
естественным фильтром через `channelOfChat`.

**Единственное хранилище.** Разговор и его канал — колонки родной таблицы `Chat`
(`channel`, `channelChatId`, `channelWho`, `channelBot`); сообщения — `Message_v2`, включая
служебные части (области размышления). Второго слоя хранения для Telegram нет.

**Паспорт проекта показывает, что изменилось.** Абзацы `==…==` рисуются рамкой (голубой бордюр,
внутренний отступ), заголовки второго уровня получили рабочие якоря — верхнее меню страницы
прокручивает к разделу.

## Какие шаги вошли, и почему

| Шаг | Что дал | Почему появился |
|---|---|---|
| 97 (10 подшагов) | сквозной путь Telegram → чат → ответ → Telegram, единственное хранилище, привязка отвечающего бота | основная задача дня |
| 98 | подсветка «что нового» в паспорте, рабочие якоря меню | параллельная просьба владельца в тот же день — «я хочу видеть, что ты добавляешь» |
| 99 | несколько ботов на владельца | явный запрос в разговоре о шаге 97 |
| 100 | лента без перезагрузки | владелец заметил пропуск: «когда я пишу в Telegram, ожидаю увидеть сразу» |
| 101 | каркас области размышления (`ChainOfThought` + Data Parts) | запрос на визуализацию хода ответа, следом за иллюстрацией через `/plan` |
| 102 | **построен и в тот же день отклонён владельцем** («откати… отвратительно») — хардкор-витрина шести demo-шагов на каждый вопрос | недопонимание сути просьбы: владелец хотел иллюстрацию механизма, не постоянный демо-балласт на реальных ответах |
| 103 | зеркалирование веб-чата в связанный Telegram, оба направления | прямой запрос после проверки шага 101 |
| 104 | пометка `Web Chat Input Message` у зеркалируемого вопроса | «в Telegram оба сообщения выглядят одинаково — нужно отличать» |
| 105 | вложения зеркалятся тоже | «мне нужно, чтобы приходили все данные» |

**Попутное, найденное и исправленное по пути:**
- лимиты сообщений (`10/час`) — шаблонные, из `vercel/ai-chatbot`, владелец их не ставил, убраны
  целиком (`lib/ai/entitlements.ts`, `lib/ratelimit.ts` удалены);
- порядок частей в Telegram-пути (`answer.ts`) — «Ход ответа» стоял ПОСЛЕ текста в массиве `parts`,
  в веб-чате читатель видел готовый ответ раньше объяснения; поправлено на естественный порядок;
- блок «Ход ответа» был невидим до первого текста (заглушка `isThinking` не учитывала
  `data-parse-step` как контент) — вся анимация играла за экраном «Waiting…»;
- настоящая причина, почему подсветка паспорта не работала НИКОГДА (не только сегодня): `Streamdown`
  санирует HTML своей схемой, тег `u` в неё не входит — три прежние попытки (шаг 98, конец августа)
  бились об этот же слой вслепую. Лечится `allowedTags`.

## Чего система не умеет, и что осталось долгом

- **настоящий разбор запроса (реестр признаков, инструменты) не перенесён** в область размышления —
  там ровно один шаг-заглушка. Перенос — отдельная, не спроектированная работа (владелец прямо
  запретил проектировать её заранее);
- отправка ответа из веб-чата в Telegram работает, но **привязка НОВОГО веб-чата к боту «на лету»**
  не построена — зеркалится только то, что уже пришло через Telegram хотя бы раз;
- подпись источника «из Telegram» в самой ленте (визуально, не в БД) — колонки есть, вида нет;
- превью изображения по клику — нет готового компонента в вендоренной библиотеке;
- аккордеон «один разговор — одна строка» на экране Telegram-бота (заказан, отложен явно владельцем
  как отдельный шаг «сразу после» текущей группы);
- голосовые сообщения из веб-чата не зеркалятся файлом (голосовой ввод расшифровывается в текст,
  байты записи никуда не уезжают);
- размер вложений при зеркалировании (base64 через JSON) не проверен на больших файлах;
- подсветка паспорта — абзацная, не пословная (ограничение `Streamdown`, названо честно).

> «код и учёт переезжают в fractera-chatbot-starter»

> «Технические решения нужно строить только так, чтобы нативные системы хранения сообщений внутри
> чата была бы единственным источником данных»

> «Хочу чтобы у нас было правильное понимание что Telegram это не контрольная точка входа… в
> большинстве случаев пользователь будет пользоваться мобильным чатом в вебе»

> выбор архитектуры ботов, дословно: **«a»** — один бот, у каждого человека свой разговор

> «взять ChainOfThought — great» (после показа развилки Reasoning/ChainOfThought)

> «Откати последнюю работу это отвратительно» — шаг 102 отменён `git revert`, без разбора по строкам

> «когда я веду общение внутри чат то вся переписка должна отзеркаливаться в связанный Telegram, как
> входящий так и исходящие сообщения»

> «сообщения которые были входящими… первое из них было исходящим и это нужно отметить… Ответы…

> «Я ни разу такого ограничения не ставил… убирай лимиты они нам не нужны»
