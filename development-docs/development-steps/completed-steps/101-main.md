## Что теперь умеет система

Под ответом ассистента — и в веб-чате, и в ответе на сообщение из Telegram — виден
раскрывающийся блок «Ход ответа» (`ChainOfThought`), несущий шаги ответа со статусом
(pending → done/error). Хранение — то же самое `Message_v2.parts`, второй базы не заводили.
Механизм проверен на ОБОИХ путях генерации: браузерном (`/api/chat`) и серверном (Telegram,
`answer.ts`, где нет открытой вкладки и стримить некому — шаг приходит сразу `done`).

🛑 **Честно про содержимое:** сегодня блок несёт РОВНО ОДИН правдивый шаг-заглушку («Модель
формирует/сформировала ответ»). Настоящие шаги разбора запроса (реестр признаков, инструменты,
чтение базы) в этот шаг не входили и не проектировались — прямой запрет владельца.

## Доказательства — две плоскости, обе живые, не макетные

1. **SQL на сервере, серверный путь (Telegram, симулирован легитимно через реальную дверь
   `/api/channels/inbound` с настоящим `hookSecret` бота, синтетический `chatId`):**
   ```
   POST /api/channels/inbound {"channel":"telegram","chatId":"proof-step-101","bot":"b1",
     "text":"Проверка шага 101: сколько будет 2+2?"}
   → {"ok":true,...,"answered":{"saved":true,"delivered":false,"reason":"Telegram refused..."}}

   SELECT role, parts FROM "Message_v2" WHERE "chatId"=(chat proof-step-101) ORDER BY "createdAt" DESC LIMIT 2;
   assistant | [{"text":"2 + 2 = 4.","type":"text"},
                {"data":{"id":"model-answer","label":"Модель сформировала ответ","status":"done"},
                 "id":"model-answer","type":"data-parse-step"}]
   ```
   Негативный контроль: самое старое сообщение-ассистента в таблице (`2026-09-03 09:09:05`,
   `parts:[]`) части `data-parse-step` не содержит — `like '%data-parse-step%'` → `f`.

2. **Живой браузер, Claude in Chrome, авторизованная сессия владельца (`qq@qq.qq`), браузерный
   путь `/api/chat`:** отправлено «Проверка шага 101 из браузера: сколько будет 3+3?» →
   скриншот показывает раскрытый блок «Ход ответа» → «✓ Модель формирует ответ» → ответ «6».
   Негативный контроль — тот же блок отсутствует у пользовательских сообщений и у сообщений без
   part `data-parse-step`.

**Тестовые разговоры удалены после проверки** (через `Delete` в самом интерфейсе чата, не SQL
напрямую) — не должны засорять историю владельца.

## Ошибки

Ни одной, найденной по ходу этого короткого шага: план был точным, `pnpm build` (единственная
доступная проверка типов для этого репозитория — `node_modules` локально нет) прошёл с первого
раза после каждого подшага.

## Что осталось долгом

- настоящие шаги разбора запроса (реестр признаков, инструменты) — отдельная будущая работа, не
  спроектирована; названо явно в ТЗ и в паспорте;
- статус `pending` для серверного (Telegram) пути недостижим физически — нет живого стрима, шаг
  всегда приходит готовым; это ограничение, а не долг.

## Эволюция навыков

нареканий — оба доказательства получены на ЖИВОЙ инфраструктуре (реальная дверь с реальным
секретом, реальная авторизованная сессия), а не на моках.
