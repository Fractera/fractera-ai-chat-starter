# Шаг 131 — «🔐 Permission: reply» вместо ответа

**Владелец:** «Работаем дальше да?» → «Нет?» → и вместо ответа бот прислал
`🔐 Permission: mcp__plugin_telegram_telegram__reply`.

## Что это значит — и это хорошая новость пополам с плохой

✅ **Исправление шага 129 сработало:** агент перестал писать в ленту сессии и вызвал инструмент
`reply` — тот самый, которым ответ доходит до Telegram.

✗ **И тут же упёрся в разрешение.** Инструмент MCP по умолчанию требует подтверждения, а
подтверждать было нечем: разрешений в `/root/.claude/settings.json` не было **вообще** — секция
`permissions` отсутствовала.

🛑 **ПОЧЕМУ РАНЬШЕ РАБОТАЛО.** Сессия шла в режиме `auto mode` (⏵⏵ на экране), который одобряет
вызовы сам. После перезапусков режим вернулся к обычному — и оказалось, что **способность агента
отвечать держалась на режиме интерфейса, а не на праве.** Режим — не гарантия: он сбрасывается
молча.

## Лечение

```json
"permissions": { "allow": [
  "mcp__plugin_telegram_telegram__reply",
  "mcp__plugin_telegram_telegram__download_attachment"
]}
```

🔒 **РАЗРЕШЕНО РОВНО ДВА ИНСТРУМЕНТА КАНАЛА, И НИ ОДНОГО СВЕРХ.** `reply` — единственный способ
агента сказать человеку хоть что-нибудь; спрашивать позволения на КАЖДЫЙ ответ бессмысленно, потому
что вопрос уходит тем же каналом, который и заблокирован. `download_attachment` — чтобы дошедший
файл можно было прочитать.

🔒 **`react` И `edit_message` НАМЕРЕННО НЕ РАЗРЕШЕНЫ:** плагин их объявляет, но без них разговор
работает целиком. Право даётся под способность, а не «на всякий случай».

✅ **Негативный контроль — главное доказательство, что права не расползлись:**
```
всего разрешений: 2
есть ли Bash без спроса: False
есть ли Write/Edit:      False
```
Границы шага 126 («агент диагностирует и предлагает, но не правит») этой правкой **не тронуты**:
разрешено говорить, а не действовать.
