# Шаг 105 — вложения зеркалятся в связанный Telegram. ЗАКРЫТ 2026-09-03

**Репозиторий и ветка:** `fractera-chatbot-starter`, `new-step-105` → `main` (`2b4e3af`). Служба
`ai-workspace:3500` не тронута — дверь `/telegram/sendFile` уже существовала (шаг 96), понадобилось
только начать её вызывать.

## Что теперь умеет система

Изображение (и вообще любое вложение — аудио, документ), приложенное к сообщению в веб-чате
связанного разговора, доезжает до Telegram как отдельное сообщение — фото/голосовое/документ по
роду `mediaType`, тем же ботом, которому принадлежит разговор. Раньше зеркалился только текст;
сообщение-только-с-картинкой не отправлялось в Telegram вовсе.

## Решение владельца, дословно

> «текстовые изображения приходят вложения фотографиями я не получаю а мне нужно чтобы на Telegram
> приходили все данные»

## Что построено

- `lib/fractera/answer.ts`: `sendFileToChannel()` — POST на уже существующую дверь службы
  `/telegram/sendFile` (`base64`, `kind`, `name`); `mirrorAttachments(parts, ...)` — берёт байты
  вложения из МЕДИАТЕКИ ПРОЕКТА тем же приёмом, что `inlineAttachmentsForModel`
  (`fetchMedia(id)` по адресу `/api/fractera/media/<id>`), для каждой части `type:"file"`.
- `route.ts`: `mirrorAttachments(...)` вызывается и для входящего (сообщение человека), и для
  исходящего (ответ модели, если инструмент вернул файл) — симметрично тексту (шаг 103).

## Доказательство

Живой браузер, разговор `@roma_armstrong`: прикреплена картинка + текст «attachment mirror test» →
журнал службы `:3500`:
```
{"id":57,...,"text":"<b>Web Chat Input Message:</b> attachment mirror test",...}
{"id":58,...,"kind":"image","objectType":"image","text":"",...}
{"id":59,...,"text":"12",...}
```
Строка 58 — сама картинка, доставлена и подтверждена Telegram (запись в журнал происходит только
после успеха, см. закон службы). Строка 59 (ответ модели) — без пометки, как и раньше.

## Ошибки

Ни одной — вторая попытка загрузки файла через `file_upload` сработала сразу (первая — по
неверному `ref` элемента, не относится к самому коду шага).

## Что осталось долгом

- голосовые сообщения из веб-чата (голосовой ввод пока не записывает файл, только расшифровывает
  в текст) — вне этого шага, никто не просил;
- предел размера не выверен отдельно для этого пути (использует существующий лимит 25 МБ
  медиатеки; путь base64 через JSON увеличивает объём ~на треть — не проверено на большом файле).

## Эволюция навыков
