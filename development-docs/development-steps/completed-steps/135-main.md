## Итоговое устройство

```
fractera-telegrambot-starter  ↔  /opt/fractera/telegrambot     порт 3600
```

В зеркале **всё**: код, `CLAUDE.md`, `.mcp.json`, `.claude/settings.json`, скрипты агента и
`scripts/install.sh`, который это ставит.

В `bootstrap.sh` осталось три места — клон, запись `.env.local` (пароль базы и `AUTH_SECRET` знает
только FES) и один вызов установщика. Пять шагов схлопнулись в один.

🔒 **ЗАКОН: УСТАНОВЩИК ЖИВЁТ РЯДОМ С ТЕМ, ЧТО СТАВИТ.** Пока установка размазана по чужому
репозиторию, каждая правка порта, процесса или запуска агента — поход туда за способностью,
которая живёт здесь.

🔒 **ПАПКА ЗАПИСЕЙ ВЫНЕСЕНА ЗА ГРАНИЦУ ЗЕРКАЛА.** `bootstrap.sh:923` делает `rm -rf` рабочей папки
при каждой установке; агенту разрешено писать в свою — значит написанное стиралось бы. Отсюда
`/opt/fractera/agent-notes` и второй `--add-dir`.

🔒 **`CLAUDE.md` ПИШЕТСЯ ДЛЯ ДВУХ ЧИТАТЕЛЕЙ, И РАЗДЕЛИТЬ ИХ НЕЛЬЗЯ.** Claude Code читает файл из
рабочей папки, а она у серверного агента и у разработчика одна и та же. Вынос в `.claude/agent.md`
со ссылкой ничего не разделяет — корневой файл всё равно общий. Шапка называет признак каждого.

## Четыре дефекта, найденных живым прогоном

**1. Модальный вопрос под pm2 = зависание. Четвёртый случай за сутки.**
Наш собственный `.claude/settings.json` вызвал вопрос, которого у пустой папки не было:
`«Is this a project you trust? This folder pre-approves 4 tool permissions»`.
🛑 **Отказ выглядел как успех везде, где можно было смотреть:** `pm2` писал `online`, процесс жил,
порт 3600 отвечал. Правду сказали только экран сессии и счётчик опрашивателей Telegram — **0**.
Лечение — `hasTrustDialogAccepted` в установщике, а не нажатие: нажатое живёт на одной машине.

**2. Два сторожа.** Старый `fractera-channel-watch` жил пять часов от руками положенного
`/opt/fractera/channel-watch.js` рядом с новым.

**3. Имена разрешений я взял из журнала шага, а не измерил.** В записи 133 они названы `reply` и
`download_attachment`; на сервере это `mcp__plugin_telegram_telegram__reply` и
`…__download_attachment`. С неверным именем разрешение не срабатывает — агент упирается в модальный
вопрос, который уходит тем самым каналом, который заблокирован.
🔒 **КОНФИГУРАЦИЯ ВОССТАНАВЛИВАЕТСЯ ИЗМЕРЕНИЕМ РАБОЧЕЙ МАШИНЫ, А НЕ ПЕРЕСКАЗОМ В ЖУРНАЛЕ.** Пересказ
был написан человеческими словами и выглядел точным.

**4. Мой рецепт определения адреса врал агенту.** Владелец спросил «домен какой?», сервер работал
по `aifa.dev`, агент ответил «домена нет, сервер по IP». Три ошибки в инструкции:
- `nginx -T | grep -m5 server_name` отдаёт первыми комментарии и `server_name _;` — мусор читается
  как «доменов нет»;
- `NEXT_PUBLIC_AUTH_URL` в `.env.local` зеркала содержит IP: его записал `bootstrap.sh` при рождении
  сервера, до включения домена. 🔒 **УСТАРЕВШЕЕ ЗНАЧЕНИЕ ОПАСНЕЕ ОТСУТСТВУЮЩЕГО** — файл есть,
  читается, выглядит свежим и врёт;
- я вовсе не назвал `FRACTERA_IP_NODOMAIN_MODE` — единственный источник правды о режиме.

Стало: обязательный порядок — сначала режим, потом адрес.

## Чего установщик дать не может — по природе, а не по недоделке

Вход в Claude по подписке (личный аккаунт владельца) и токен бота с allowlist (его секрет).
Установщик проверяет `/root/.claude/.credentials.json` и `/root/.claude/channels/telegram/.env` и
**называет недостающее строкой в журнал** — молчащий бот без объяснения читается как поломка
продукта.
