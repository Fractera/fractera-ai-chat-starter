# Шаг 104 — пометка «Web Chat Input Message» у зеркалируемого вопроса. ЗАКРЫТ 2026-09-03

**Репозитории:** `fractera-chatbot-starter` (`0c6a70d`), `ai-workspace` (служба `:3500`, `6ce967a1`).

## Что теперь умеет система

Сообщение, зеркалируемое из веб-чата в связанный Telegram (шаг 103), теперь различимо: вопрос
человека приходит с жирной пометкой `Web Chat Input Message:` перед текстом, ответ модели —
без пометки, как обычный ответ бота.

## Решение владельца, дословно

> «сообщения которые были входящими... но в чате первое из них было исходящим и это нужно
> отметить так: `<b>Web Chat Input Message:</b>` bla bla bla. Ответы... маркировать не нужно.
> Я отметил жирным... если это возможно?»

## Что построено

- `ai-workspace/services/channels/server.js`: `send(token, chatId, text, parseMode)` —
  необязательный 4-й параметр, по умолчанию не передаётся Telegram вовсе (старое поведение всех
  остальных вызовов не тронуто); дверь `/telegram/send` принимает `parseMode` в теле запроса,
  белым списком — принимается только строка `"HTML"`.
- `fractera-chatbot-starter/lib/fractera/answer.ts`: `escapeTelegramHtml()` — экранирует `& < >`
  в тексте человека (не полный HTML-набор: ровно то, что Telegram трактует как разметку), чтобы
  чужой `<b>` внутри вопроса не стал настоящим тегом; `sendToChannel(...)` — необязательный 5-й
  параметр `parseMode`, форвардится в тело запроса к службе.
- `route.ts`: только зеркало ВХОДЯЩЕГО (вопрос человека) оборачивается в
  `` `<b>Web Chat Input Message:</b> ${escapeTelegramHtml(mirrorText)}` `` с `parseMode: "HTML"`.
  Зеркало ИСХОДЯЩЕГО (ответ модели, в `onEnd`) не тронуто — идёт как раньше, без пометки.

## Доказательство

Живой браузер, разговор `@roma_armstrong`: напечатано «label test eight plus eight» → журнал
службы `:3500`:
```
{"id":49,...,"text":"<b>Web Chat Input Message:</b> label test eight plus eight",...}
{"id":50,...,"text":"16",...}
```
Строка 49 принята Telegram (иначе `send()` не записала бы её в журнал — служба пишет только то,
что Telegram подтвердил), значит `parse_mode: "HTML"` был для него валиден и сообщение отрисуется
жирным в самом приложении. Строка 50 (ответ) — без тегов, как и требовалось. Негативный контроль —
сообщения 47/48 (обмен «6+666», пришедший через сам Telegram, не через веб-зеркало) тоже без
пометки — механизм различает источник верно.
