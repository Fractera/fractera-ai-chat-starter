# Шаг 128 — аудит защищённого режима и кнопки, невидимые в одной из тем

## Вопрос владельца: можем ли быть уверены, что (1) незащищённый режим заблокирован, (2) защищённый защищает

Он переключил сервер в защищённый режим и попросил проверить. Проверено измерением, включая то,
что измерить **нельзя** — это названо отдельно.

## ✅ 1. Незащищённый режим заблокирован — да

```
FRACTERA_IP_NODOMAIN_MODE=false   в app, bridges/app, services/auth  (все три)

БЫЛО (утро):  POST /api/fractera/pty-ticket → 200 {"ticket":"…"}   ← билет выдавался БЕЗ сессии
СТАЛО:        POST /api/fractera/pty-ticket → 307 → /welcome        ← билет не выдан
              GET  /terminal                → 307 → /welcome
              GET  /api/fractera/agent-setup→ 307 → /welcome
              GET  admin.aifa.dev/          → 307 → auth.aifa.dev/register
              двери /api/architect/*        → 401
```

🔒 **ЭТО ЗАКРЫЛО ДЫРУ, НАЙДЕННУЮ УТРОМ:** терминал боевой машины отвечал из интернета без сессии.
Запись «СРОЧНО» в `BACKLOG` закрыта переключением режима, а не отдельной работой.

## ✅ 2. Защищённый режим защищает — в главном да

```
ufw            active · default deny (incoming) · разрешены 22/80/443, и только они
iptables       -P INPUT DROP · ufw-user-input: ACCEPT только 22, 80, 443
docker         контейнеров 0, цепочка DOCKER = DROP → обхода ufw нет
TLS            :443 слушает, сертификат /etc/letsencrypt/live/aifa.dev
HTTP→HTTPS     aifa.dev, chat.aifa.dev, admin.aifa.dev → 301 на https
```

## 🛑 Три оговорки, названные, а не замолчанные

### а) Внешнюю достижимость портов 3000+ изнутри проверить НЕЛЬЗЯ

```
ip route get 213.199.61.7  →  local … dev lo
```

Пакет к собственному внешнему адресу **не выходит наружу** и не проходит фильтр внешнего
интерфейса. Поэтому `curl http://213.199.61.7:3000/` с сервера отвечает `200` **и это ничего не
говорит** о доступности снаружи.
🔒 **ЧТО МОЖНО УТВЕРЖДАТЬ:** по правилам `ufw` и `iptables` порты 3000/3001/3002/3600/9621 снаружи
закрыты — политика `DROP`, исключений для них нет. Это вывод из конфигурации, и он сильный.
🛑 **ЧЕГО УТВЕРЖДАТЬ НЕЛЬЗЯ:** что это проверено эмпирически. **Решающая проверка — телефон по
мобильной сети:** `http://213.199.61.7:3600` должен не ответить вовсе.

### б) Слой архитектора отдаёт страницу без сессии

```
GET /ru/architect/telegram?section=settings  →  200, и по IP, и через домен
  видна форма токена бота          : да
  видна карточка подписки          : да
  виден реестр признаков           : да
  виден маскированный токен        : НЕТ
  двери /api/architect/*           : 401
```

🛑 **ЭКРАН ВИДЕН, ДАННЫЕ — НЕТ.** Секреты не утекают: маска не отдаётся, двери отвечают `401`.
Утекает **структура**: названия разделов, состав настроек, наличие реестра. Это долг, а не
катастрофа, и он занесён в `BACKLOG` — закрывать отдельной работой, потому что задевает `proxy.ts`
шаблона и все гостевые проекты.

### в) По IP на `:80` переадресации на HTTPS нет

Обращение с `Host: 213.199.61.7` отдаёт публичный сайт по открытому HTTP. Отдельного
`server_name` для IP в nginx нет — запрос попадает в блок по умолчанию.
🔒 **И иначе быть не может:** сертификат на IP-адрес не выдаётся, редирект на HTTPS по IP вёл бы в
ошибку сертификата. Ограничение названо, чтобы не выглядело недосмотром.

## 128. Кнопки терминала пропадали в одной из тем

**Владелец:** «в дневной теме они выглядят хорошо, а в ночной их не видно».

Панель терминала **всегда** тёмная (`#0b0b0c`) — это цвет оболочки, а не оформления страницы. Кнопки
же были `variant="ghost"` и брали `text-foreground` из темы: в одной из тем красились под светлый
фон, которого здесь нет никогда.

🔒 **ПРАВИЛО ШИРЕ СЛУЧАЯ: ЭЛЕМЕНТ НА ФОНЕ, НЕ ПОДЧИНЁННОМ ТЕМЕ, ОБЯЗАН ИМЕТЬ СОБСТВЕННЫЙ ЦВЕТ.**
Токен темы поверх фиксированного фона — ставка на то, что тема угадает чужой фон, и половину времени
ставка проигрывает.

**Доказательство:** класс есть в 2 собранных чанках, «Сессия агента» — в 1, негативный контроль
(выдуманный класс `text-lime-999`) — **0**. Проверять по HTTP нечем: `/terminal` теперь под замком,
и это само по себе доказательство пункта 1.

✗ **Ошибка по пути:** JSX-комментарий поставлен перед корневым элементом `return` — сборка не
компилировалась (`TS1005`). Поймано `tsc` до доставки.
