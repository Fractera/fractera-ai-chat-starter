### Дорогие факты — НЕ добывать заново

Все с адресами лежат в файле исследования; здесь только то, что решает направление:

- **надёжность даёт КОНСТРУКЦИЯ, а не класс модели** — на верхних ступенях принуждения выбор делает
  наш код, и mini влияет лишь на заполнение аргументов;
- **«не более пяти инструментов» — совет по промпту, а не предел**; предел снимается `activeTools`;
- **«навыков» для `ToolLoopAgent` в SDK НЕТ** — они только у `HarnessAgent`, то есть проброс в чужой

- **реранкер многоязычный есть, но провайдеры Cohere/Bedrock/Together — второй ключ**;
- **эмбеддинги у нас уже стоят**: `text-embedding-3-small`, 1536, `sqlite-vec`;
- **неподдержанная настройка провайдером игнорируется МОЛЧА**; единственный прибор — `result.warnings`.

Канал разговора — колонки родной таблицы `Chat` (`channel`, `channelChatId`, `channelWho`,

машине: Telegram шлёт по числовому `chat_id`, имя — переменное, разбирать заголовок кодом нельзя.

### Telegram — не главный вход

> «Telegram это не контрольная точка входа. Когда к нам приходит новое приложение в нём уже есть
> ссылка на чат, и Telegram здесь только расширение функциональности для редких кейсов; в
> большинстве случаев пользователь будет пользоваться мобильным чатом в вебе»

Браузерный путь генерации (`POST /api/chat`) — основной и не переделывается; серверный путь
(`answer.ts`, `answerInboundMessage`) — обязательный, но побочный: нужен только потому, что у
сообщения из Telegram нет браузера.

### Вариант A — один бот, много собеседников (не пул ботов с раздельными токенами)

Его слово: **«a»**. Разговор адресуется парой «бот × собеседник» (`conversationId`), а не общим
пулом. Несколько ботов на владельца — да; несколько независимых токенов на одну учётную запись без
привязки к конкретному собеседнику — нет.

### Область размышления — ChainOfThought, не reasoning

`reasoning` AI SDK несёт текст, который порождает МОДЕЛЬ о своём ходе — не годится для наших шагов
(запрос к БД, реестр, инструмент), которые рождает наш код. `ChainOfThought` + Data Parts
(`type:"data-parse-step"` в `Message_v2.parts`) — персистентно, без второй таблицы.

### Построенное согласуется глазами владельца

Зелёные доказательства отвечают на вопрос «работает ли» и не отвечают на «то ли это». Экран, вкладка,
форма — предъявляются построчно после доставки, следующий подшаг открывается только после его слова.

**Служба каналов `:3500`** (`ai-workspace/services/channels/server.js`):

шага 96; файлы — медиатека `:3300` (`lib/fractera/media.ts` → `fetchMedia`/`uploadToMedia`), не

🛑 **ГЛАВНОЕ ОГРАНИЧЕНИЕ ДВИЖКА: ГЕНЕРАЦИЮ ЗАПУСКАЕТ БРАУЗЕР.** `useChat` шлёт `POST /api/chat`, и
ответ рождается в стриме этого запроса — сообщение из Telegram приходит, когда браузера нет вовсе.

🛑 **СЛУЖБА ТОЛКАЕТ ВХОДЯЩЕЕ РОВНО ОДНОМУ АДРЕСУ.** Второй адрес хука не существует — переключение
`hookUrl` отключает разбор запроса в `fractera-next-starter`, если он там ещё раз понадобится.

🛑 **`Streamdown` (паспорт, `fractera-next-starter`) санирует HTML своей схемой поверх результата
`remarkPlugins`.** Тег, которого нет в `hast-util-sanitize`'s `defaultSchema` (например `u`),
пропадает молча, даже если плагин верно его построил. Лечение — `allowedTags={{tag: []}}`
у `<Streamdown>`, штатный параметр, а не обход.

🛑 **Сайдбар чата — ненадёжный источник правды для «что удалено/сохранено».** Тост об успехе не
значит, что клиентский список ревалидировался. Проверка — прямой SQL или та же дверь API
(`fetch('/api/chat?id=...', {method:'DELETE'})`), не текст на экране.
