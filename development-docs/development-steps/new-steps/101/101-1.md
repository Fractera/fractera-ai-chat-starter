# 101-1 — тип данных + запись реального шага в браузерном пути

## 1. Что строится

- `ParseStepData` в `lib/types.ts`: `{ id: string; label: string; status: "pending" | "done" | "error" }`.
- Запись `"parse-step": ParseStepData` в `CustomUIDataTypes` (рядом с `"waiting-status"`, не трогая её).
- В `app/(chat)/api/chat/route.ts`, внутри уже существующего `createUIMessageStream({ execute: ({ writer }) => ... })`:
  `writer.write({ type: "data-parse-step", id: "model-answer", data: { id: "model-answer", label: "Модель формирует ответ", status: "pending" } })`
  ДО вызова `streamText`, и повторно с `status: "done"` после получения текста — БЕЗ `transient` (часть обязана остаться в истории).

## 2. Что считается готовым

Одна фраза: сохранённое в `Message_v2` сообщение ассистента несёт в `parts` объект с
`"type":"data-parse-step"` и `"status":"done"`.

## 3. Чем доказывается — две плоскости, названы заранее

- **SQL на сервере** (`psql` к базе чата): `SELECT parts FROM "Message_v2" WHERE id = '<id только что отвеченного>'` — в выводе есть `data-parse-step` / `done`.
- **Негативный контроль:** тот же запрос на сообщение, отвеченное ДО этой правки, — части `data-parse-step` в нём нет.

Ничего — первый подшаг.
