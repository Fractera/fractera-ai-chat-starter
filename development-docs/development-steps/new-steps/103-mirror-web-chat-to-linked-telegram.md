# Шаг 103 — зеркалирование веб-чата в связанный Telegram

**Заведён 2026-09-03 прямым словом владельца, план согласован через plan-mode в той же сессии.**

## 1. Пересказ и решения владельца

**Своими словами.** Цикл Telegram → чат → модель → Telegram уже работает. Если человек продолжает
ТОТ ЖЕ разговор в браузере (печатает вопрос в веб-чате), это сообщение и ответ на него не попадают
в Telegram. Нужно, чтобы весь разговор — обе стороны — зеркалился в связанный Telegram, когда
разговор к нему привязан.

**Решение владельца, дословно, 2026-09-03:**

> «Нужно сделать чтобы когда я веду общение внутри чат то вся переписка должна отзеркаливаться в
> связанный Telegram, как входящий так и исходящие сообщения»

**Мои допущения, названные вслух:**
- «связанный» = разговор, у которого уже есть `Chat.channelChatId`/`channelBot` (пришёл когда-то из
  Telegram). Разговор, заведённый в браузере «New chat» без всякой связи с Telegram, зеркалить
  некуда — привязка нового веб-чата к боту не спрашивалась и в шаг не входит;
- зеркалируется только ТЕКСТ (вопрос человека и финальный ответ модели), не вложения — отдельная
  будущая работа.

## 2. Разведка переиспользуемого — измерено 2026-09-03

| Что | Где | Состояние |
|---|---|---|
| адрес бота и chatId разговора | `lib/fractera/channels.ts` → `channelOfChat(chatId)` → `{channel, chatId, bot} \| null` | готово; `null` = разговор не связан — естественный фильтр |
| отправка текста в Telegram | `lib/fractera/answer.ts` → `export async function sendToChannel(...)` | готово, уже используется в `answerInboundMessage`, не бросает исключений |
| текст из `parts` | `lib/fractera/answer.ts` → `function textOf(parts)`, не экспортирована | экспортировать, не копировать вторую версию |
| сохранение сообщения человека (браузер) | `app/(chat)/api/chat/route.ts:215-227` | точка зеркалирования входящего |
| сохранение готового ответа (браузер) | тот же файл, `onEnd` (не-`isToolApprovalFlow`) | точка зеркалирования исходящего |

## 3. Известные ограничения

| Инвариант | Что случится при нарушении |
|---|---|
| закон единственного хранилища (шаг 97) | зеркалирование не заводит копию сообщения в БД — только отправку наружу, `Message_v2` остаётся единственной правдой |
| `sendToChannel` не бросает исключений | если бы бросала — отказ Telegram уронил бы ответ пользователю в браузере, этого нельзя допустить |
| ответ тем же ботом, которому принадлежит разговор (закон шага 97-10) | `channelOfChat` уже возвращает `bot`, передаётся в `sendToChannel` как есть |

## 4. Наблюдаемые результаты

1. Вопрос, напечатанный в браузере в связанном разговоре, появляется в Telegram.
2. Ответ модели на этот вопрос появляется в Telegram следом.
3. Тот же сценарий в НЕсвязанном чате ничего в Telegram не отправляет.

## 7. Чего в шаг не входит
